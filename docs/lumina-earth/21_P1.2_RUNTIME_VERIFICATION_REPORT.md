## 4. Repeatable Browser Verification Harness

To provide a durable verification foundation without altering application boundaries or introducing paid dependencies, a dedicated harness was created.

### 4.1 Harness Specification
- **Path:** `scripts/verify_earth_runtime.mjs`
- **Invocation Command:**
  ```powershell
  node scripts/verify_earth_runtime.mjs
  ```
- **Dependencies:** Zero external npm packages. Built entirely on standard Node.js (v24.12.0) built-in modules (`node:child_process`, `node:fs`, `node:path`, native `fetch`, and native `WebSocket`).
- **Engine:** Headless Chromium 156 with ANGLE Direct3D11 acceleration.
- **Protocol:** Chrome DevTools Protocol (CDP) over WebSocket.

### 4.2 Safety & Process Isolation Rules
1. **Server Reachability Guard:** The harness first queries `http://127.0.0.1:8764/`. If the server is offline, it aborts immediately with clear startup instructions rather than spawning rogue background instances or attempting process termination.
2. **Dedicated User Data Dir:** Browser is launched with a scratch profile (`scratch/chr_earth_harness`) to prevent session pollution.
3. **Guaranteed Teardown:** A `finally` block guarantees child browser termination (`process.kill()`) and scratch profile cleanup.
4. **Bounded Waits:** Every interaction uses bounded polling loops with explicit timeout cutoffs (no infinite hanging).
