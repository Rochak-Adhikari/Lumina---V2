# Function contracts and types
All names marked proposed are design targets, not implemented interfaces. No production code is supplied here. Existing dataclasses and enums are preferred to a new framework. Contracts describe the minimum complete unit; do not create a new file/class for each function.

## Types and common rules
Extend `computer_action.py` compatibly: keep existing IntendedAction/TargetEvidence/Verification fixtures. Proposed `DesktopProposal` is a discriminated dataclass union: Move(point), Click(point,button,count), Scroll(point,axis,amount), Drag(start,end,duration), Key(key), Text(text), Chord(keys), Focus(window), Wait(condition), Ask(question), Done(predicate). Exactly one variant, strict fields, no coercion of bool to int, no NaN/infinity/code/native payload. Proposed `TargetBinding` includes owner/task generation, sharing session/sequence, source, geometry revision, window/process creation identity and inference→dispatch revalidation proof. Proposed `DesktopIntent` adds action ID, immutable variant/target, trusted risk, exact approval binding, deadline and typed postcondition. Extend ExecutionResult/Verification with named typed checks while preserving existing digest constructors.

Proposed aliases: `Point=(float,float)` in [0,1) frame coordinates; `PhysicalPoint=(int,int)` in physical virtual desktop; `WindowIdentity=(hwnd,pid,creation_id,class_name,window_generation,desktop_id)`; `Geometry=(origin,size,scale,revision)`; `ObservationRef=(stream_session,source,sequence,geometry_revision)`; `Postcondition` union of focused(window), text_digest(control,digest), property_equals(control,name,value), visible_region(label/bounds), goal_all(checks), unverifiable(reason). Model-supplied labels are hypotheses; trusted verifier establishes evidence independently. `Receipt` carries attempted/submitted counts, IDs, times, epoch, partial/error, potentially-held inputs and cleanup uncertainty; never raw secret text. `Verdict=matched|failed|inconclusive|not_run|stale`. Proposed `ModelResult=proposal|clarification|no_action|transport_failure`.

Reuse ActionState and TaskManager statuses as ARCHITECTURE.md specifies. `SafeError(code, may_have_effect, retry_read_only, summary)` is structured. Unknown effects default inconclusive and quarantine; failed postcondition never proves no intermediate effect. IDs and monotonic deadlines are generated locally, not by the model.

Every async function below takes an implicit current task cancellation/generation context and absolute deadline. Check before and after awaits. Default scheduling bounds are proposed starting controls: provider 30 s; existing controller default 5 s plus bounded cleanup (configurable, not a hard OS-call bound); existing UIA helper 12 s; observation/action budgets set from native measurements, not extended to conceal failure. Test clocks are injected. Timeout of a submitted OS action is unknown, not no-effect. Cancellation requests never prove a worker/native call stopped. Evidence metadata is bounded and excludes raw image/text. All listed unit/native tests are proposed unless linked by CURRENT_STATE_AUDIT.md to existing names.
